## 教学约定

- 每次只讲一个小节，聊天正文以约 1500—2000 个中文字为参考，自然调整。
- 合并讲解例外（2026-11-08）：用户先后明确要求一次讲完第四、六、七章，各章末统一答疑；不据此自动连讲后续章节。
- 顺序：为什么需要 → 概念是什么 → 本项目如何实现 → 如何与其他模块协作。
- 在聊天中完整提供解释、例子、必要代码及配图；不要求打开笔记才能学习。
- 首次出现英文缩写说明全称和含义；类比后说明对应的真实实现。
- 每节只选少量关键文件和函数；区分通用原理与本项目的具体选择。
- 优先中文 Mermaid；无法渲染时使用文本示意图；注明图中省略的细节。
- 讲完停留答疑，不自动推进；用户不懂时换解释，不考试，不连续提多个问题。
- 每节末提示：“本节先到这里。你可以继续提问，或告诉我进入下一节。”
- 笔记记录结论、术语、实现要点、相对路径代码链接、必要图示、易混淆点及重要答疑，不复制聊天全文。
- 每次讲课或重要答疑后更新对应笔记和进度，提供简短可点击链接。
- 不提前生成未讲小节的笔记。
- 只允许维护教学文档：不修改业务代码、不安装依赖、不调用收费模型接口；发现问题只记录。
- 当前结论来自源码静态阅读，未运行验证。历史评估注明日期；依赖声明不等于业务实际使用。
