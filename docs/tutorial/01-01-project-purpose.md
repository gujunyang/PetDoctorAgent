# 1.1 项目解决什么问题

状态：已讲解／答疑中。讲解日期：2026-11-06。尚未由用户确认理解。

## 核心结论

- PetDoctorAgent（宠医通）是面向宠物咨询场景的命令行 AI 应用演示，将模型、知识检索、档案/历史、业务工具及流程控制组织起来。
- 一次实际咨询除理解语言外，还需确认对象、补充信息、查资料/历史、选择处理职责并关注风险；模型只承担其中部分工作。
- 当前支持身份识别、问诊、产品知识推荐、病历汇总、安全分级及记忆相关代码路径；“存在实现”不等于已经证明可靠。
- 工作台、小程序和管理后台属于规划；预约和库存查询已下线。原型图、产品需求不等于可运行入口。
- 多 Agent 指职责划分与编排，不意味着多个独立训练的模型，也不意味着所有节点均调用模型。

## 术语简释

| 术语 | 本节含义 |
|---|---|
| AI（Artificial Intelligence） | 人工智能 |
| Agent | 智能体：通常利用模型理解任务，并结合工具、状态及执行逻辑完成工作；不同系统能力范围不同 |
| CLI（Command-Line Interface） | 命令行界面：在终端输入文字、读取输出 |
| Supervisor / Worker | 调度角色 / 具体任务处理角色 |
| 工具 | 程序可实际执行的功能，如检索资料、按编号查询病历 |

## 当前能力边界

| 能力 | 当前实现与限制 |
|---|---|
| 身份与档案 | 按编号/名字匹配，信息足够可建档，否则追问 |
| 问诊与产品推荐 | 有模型节点和知识检索接入；输出正确性不能仅由代码存在推断 |
| 病历查询 | 汇总本地档案/历史及可用外部工具；内置服务返回演示病历 |
| 安全审查 | 有关键词和模型审查，但历史报告记录首句急诊被身份门控阻断的问题 |
| 记忆 | 有数据库与进程内回退实现；跨重启保存取决于实际存储方式 |
| 预约/库存 | 已下线，命中请求时回复暂不支持 |
| 工作台/小程序/后台 | 规划与原型，不是当前业务入口 |

## 易混淆点

- 模型说“查到了”与程序实际查询工具不同，要看调用与数据来源。
- Agent 名称表示职责，不证明存在独立模型或自主工具循环；病历节点是确定性处理。
- 项目中的多角色可使用同一模型配置。
- 产品推荐能力不包含当前门店库存能力。
- 安全机制已实现不代表每条路径都受其覆盖，也不代表输出经过医学验证。
- 本节的示例用于说明需求，不是实际运行输出。
